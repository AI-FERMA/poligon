Токен

Что это. Единица текста для модели: часть слова, слово или знак; примерно 3–4 символа русского текста. Контекст, цена и скорость считаются в токенах.

Простыми словами. Токен — это «кусочек текста», которым модель платит за чтение и письмо.

Когда нужен. Когда оцениваешь объём контекста, стоимость диалога или скорость генерации.

Контекстное окно

Что это. Максимальный объём токенов, который модель видит за один вызов: системный промпт, история, фрагменты RAG, описания инструментов, ответ.

Простыми словами. Это стол, на котором модель раскладывает всё, что читает; стол конечен.

Когда нужен. При проектировании промпта, выборе top-k, сжатии истории, выборе модели.

Температура

Что это. Параметр случайности выбора следующего токена: 0 — почти детерминированно, 1 — разнообразно. Не влияет на знания и факты.

Простыми словами. Ручка «насколько смело модель угадывает следующее слово».

Когда нужен. Настройка сценариев: 0–0,2 для фактов и structured output, выше — для творческих формулировок.

Галлюцинация

Что это. Уверенное утверждение модели, не подтверждённое источниками или фактами: выдуманный тариф, несуществующая статья договора, неверная дата.

Простыми словами. Модель говорит уверенно то, чего нет в источниках.

Когда нужен. Всегда: это главный риск доверия в банке; меряется как hallucination rate на выборке.

Системный промпт

Что это. Инструкция модели, задающая роль, правила, формат, границы и стиль; действует на весь диалог; версионируется и тестируется как код.

Простыми словами. Должностная инструкция агента, написанная один раз для всех разговоров.

Когда нужен. Проектирование поведения агента; каждое изменение — релиз через eval gate.

Structured output

Что это. Ответ модели в заданной схеме (JSON Schema): поля, типы, перечисления — чтобы код мог надёжно разобрать результат.

Простыми словами. Модель заполняет анкету с полями, а не пишет сочинение.

Когда нужен. Извлечение параметров, классификация, вызов инструментов, числа и даты.

Function calling / tool use

Что это. Механизм, при котором модель возвращает структурированный вызов функции (имя + аргументы), а код исполняет его и возвращает результат модели.

Простыми словами. Модель не нажимает кнопки сама — она говорит коду, какую кнопку нажать.

Когда нужен. Любой доступ агента к данным и действиям: баланс, история, поиск, перевод.

Агент

Что это. LLM в цикле: получает цель, выбирает инструмент, наблюдает результат, повторяет до достижения цели или лимита; порядок шагов выбирает модель.

Простыми словами. Сотрудник с целью и ящиком инструментов, которому поставили лимиты.

Когда нужен. Длинный хвост запросов, где сценариев слишком много для кода; только с ограничителями.

Workflow (оркестрация)

Что это. Последовательность шагов, заданная кодом, где LLM выполняет отдельные узлы: классифицировать, извлечь, сформулировать.

Простыми словами. Конвейер: станки стоят на местах, модель работает на станке.

Когда нужен. Мало путей (≤ 10), необратимые действия, требования объяснимости.

HITL (human in the loop)

Что это. Человек в контуре: подтверждение клиента перед действием или участие оператора в решении.

Простыми словами. Перед тем как сделать что-то необратимое, спрашиваем человека — кнопкой.

Когда нужен. Запись, финансовые и регуляторно значимые действия; эскалация при неуверенности.

Идемпотентность

Что это. Свойство операции: повторный вызов с тем же ключом даёт тот же результат, не создавая дубль.

Простыми словами. Квитанция: повторный запрос с той же квитанцией не делает второй перевод.

Когда нужен. Каждый вызов инструмента записи: переводы, заявки, изменения продуктов.

RAG

Что это. Retrieval-augmented generation: поиск релевантных фрагментов знаний и подстановка их в контекст перед генерацией, с цитированием.

Простыми словами. Библиотекарь приносит карточки, стажёр отвечает по ним и указывает источник.

Когда нужен. Любые ответы по документам банка: тарифы, регламенты, инструкции.

Чанк

Что это. Фрагмент документа — единица индексации и поиска; обычно 300–800 токенов, режется по структуре, с перекрытием и метаданными.

Простыми словами. Карточка из библиотеки: короткая выписка с указанием, откуда.

Когда нужен. Настройка индексации базы знаний; spike по размеру чанка.

Эмбеддинг

Что это. Числовой вектор, кодирующий смысл текста; близкие по смыслу тексты — близкие векторы; основа векторного поиска.

Простыми словами. Координаты смысла: похожие фразы оказываются рядом.

Когда нужен. Индексация чанков и запросов; выбор модели эмбеддингов под русский язык.

Гибридный поиск и reranking

Что это. Объединение векторного и ключевого поиска (RRF) с последующей переоценкой кандидатов моделью-reranker'ом по релевантности запросу.

Простыми словами. Два поисковика приносят кандидатов, эксперт переставляет лучших наверх.

Когда нужен. Когда запросы содержат и смысл, и точные идентификаторы; почти всегда в банке.

recall@k

Что это. Доля вопросов golden set, для которых нужный фрагмент попал в top-k результатов поиска; метрика retrieval.

Простыми словами. Из 100 вопросов библиотекарь принёс нужную карточку в 87 — это и есть recall.

Когда нужен. Диагностика RAG: низкий recall — чинить поиск, не модель.

Faithfulness (groundedness)

Что это. Доля утверждений ответа, подтверждённых принесёнными фрагментами; метрика генерации в RAG; оценивается судьёй или человеком.

Простыми словами. Стажёр не выдумал сверх карточек.

Когда нужен. Контроль галлюцинаций при хорошем поиске.

ОПЭ / ПРОМ

Что это. Опытно-промышленная эксплуатация — работа на реальных данных для ограниченного круга с усиленным контролем; ПРОМ — промышленная эксплуатация для всех после допусков.

Простыми словами. Сначала ограниченный круг под присмотром, потом все.

Когда нужен. Планирование пути запуска и вех с допусками ИБ, ПДн, нагрузки.

C4-схема

Что это. Нотация архитектурных схем в четырёх уровнях: контекст, контейнеры, компоненты, код. Для агента на доске — уровень контейнеров.

Простыми словами. Карта города: районы (контейнеры) и дороги (данные), без планов домов.

Когда нужен. Объяснение архитектуры на собеседовании и в документе видения.

Golden set

Что это. Эталонный набор реальных запросов с рубрикой ожидаемого ответа для офлайн-оценки; 200–1 000 примеров, стратифицированный, обновляемый.

Простыми словами. Экзаменационные билеты из реальных вопросов клиентов.

Когда нужен. Сравнение версий промптов и моделей; eval gate.

LLM-as-judge

Что это. Использование модели как оценщика ответов по рубрике; валиден после калибровки на человеческой разметке (согласие ≥ 85%).

Простыми словами. Дегустатор, которого сначала проверили на блюдах с известной оценкой.

Когда нужен. Масштабирование оценки на сотни примеров и еженедельный мониторинг.

Eval gate

Что это. Ворота релиза: набор порогов на golden set (балл, критические кейсы, p95, стоимость), без прохождения которых версия не идёт дальше.

Простыми словами. Экзамен, без которого к клиентам не пускают.

Когда нужен. Каждый релиз поведения: промпт, модель, база знаний, пороги.

Prompt injection

Что это. Атака: инструкции модели в тексте клиента (прямая) или в данных — документе, письме, ответе API (косвенная), меняющие поведение агента.

Простыми словами. Злоумышленник подсовывает услужливому стажёру бумажку с приказом.

Когда нужен. Модель угроз, red-team, архитектура guard и границ.

Guardrails

Что это. Защитный контур вокруг модели: входные и выходные фильтры (инъекции, PII, тематика, токсичность, финсоветы), валидаторы формата и цитат; отдельные сервисы с тестами.

Простыми словами. Охранники на входе и выходе, которые читают каждую бумажку.

Когда нужен. Любой клиентский агент; требование ИБ для допуска.

Red-team

Что это. Набор атак и процесс их проведения против агента: инъекции, утечки, злоупотребление инструментами; результат — тест-кейсы в eval gate.

Простыми словами. Каскадёры, которые пытаются сломать агента до злоумышленников.

Когда нужен. Перед ОПЭ/ПРОМ и при добавлении инструментов.

PII / ПДн

Что это. Персональные данные и банковская тайна: ФИО, паспорт, счета, операции; не покидают контур банка без обезличивания и правового основания.

Простыми словами. То, что не выносят из хранилища.

Когда нужен. Выбор размещения модели, фильтры, логирование, доступ к документам.

p95 / перцентили

Что это. p95 — значение, быстрее которого обслуживаются 95% запросов; показывает хвост, который скрывает среднее.

Простыми словами. «95 из 100 ответов быстрее 5 секунд».

Когда нужен. SLO, бюджет латентности, нагрузочные тесты.

TTFT и streaming

Что это. Time to first token — задержка до первого токена ответа; streaming — показ токенов по мере генерации, снижающий воспринимаемую латентность.

Простыми словами. Официант приносит блюдо по кусочкам: первый — сразу.

Когда нужен. Любой чат-канал; бюджет латентности.

SLO / SLI / error budget

Что это. SLI — измеряемый показатель; SLO — цель по нему на окне; error budget = 1 − SLO — допустимый объём нарушений, валюта для релизов и рисков.

Простыми словами. Обещание «работаем 99,5% времени» с запасом на ошибки, который тратят осознанно.

Когда нужен. Договорённости о надёжности с заказчиком и командой.

Каскад моделей

Что это. Маршрутизация запросов по сложности: малая модель решает простые интенты, большая — сложные; с fallback и eval по каждой ветке.

Простыми словами. Простые вопросы — стажёру, сложные — эксперту; и проверяем обоих.

Когда нужен. Снижение стоимости и латентности при сохранении качества.

Стоимость диалога

Что это. Unit-экономика: сумма по ходам (входные × цена + выходные × цена) плюс поиск, guard, инфраструктура; для on-prem — стоимость GPU-часа на токены при загрузке.

Простыми словами. Счёт за каждый разговор: больше всего — за чтение.

Когда нужен. Бюджет, ROI, выбор модели, оптимизация промпта.

CJM

Что это. Customer journey map — карта пути клиента по шагам задачи: действия, каналы, время, эмоции, боль, стоимость для банка, место для агента.

Простыми словами. Маршрут клиента с отметками, где больно и дорого.

Когда нужен. Выбор сценариев и точек встраивания агента.

Containment rate

Что это. Доля диалогов, завершённых без передачи оператору; продуктовая метрика эффективности, валидна только в паре с task success и CSAT.

Простыми словами. Сколько разговоров консультант закрыл сам — без вопроса, помог ли.

Когда нужен. Экономика и дашборд агента.

Task success rate

Что это. Доля диалогов, где задача клиента решена: по разметке выборки, поведенческому прокси (нет повторного обращения за 7 дней) и сигналу клиента.

Простыми словами. Клиент ушёл с решённой задачей и не вернулся с тем же вопросом.

Когда нужен. Главная продуктовая метрика качества; множитель в экономии.

Guardrail-метрика

Что это. Метрика-ограничитель в дашборде: не должна ухудшаться при росте главной (hallucination rate, жалобы, эскалации по гневу, p95, стоимость).

Простыми словами. Красные линии, за которые нельзя заходить ради главной цели.

Когда нужен. Любой дашборд и любое решение о релизе.

ADR

Что это. Architecture decision record — короткий документ: контекст, варианты, решение, последствия, дата пересмотра; фиксирует ключевые технические решения.

Простыми словами. Карточка «почему мы так решили и когда передумаем».

Когда нужен. Выбор модели, размещения, БД, схемы HITL, судьи.

Веха (milestone)

Что это. Проверяемый результат в roadmap: что + критерий + дата + владелец; не активность и не длительность.

Простыми словами. Отметка на дороге, которую видно и можно проверить.

Когда нужен. Квартальный план, статусы заказчику.

Spike

Что это. Time-boxed исследовательская задача с гипотезой, метрикой и измеримым выходом; формат для ML-работы с неопределённым исходом.

Простыми словами. Короткий эксперимент с цифрами на выходе.

Когда нужен. «Улучшить качество», выбор модели, чанкинг, судья.

DoD для ИИ-задачи

Что это. Определение готовности: версии кода/промпта/конфига, eval на golden set не хуже базы, критические кейсы 0, red-team для новых инструментов, трасса и метрики, feature flag, документация.

Простыми словами. Чек-лист, без которого задача не считается сделанной.

Когда нужен. Каждая история, меняющая поведение агента.

Канарейка / shadow

Что это. Shadow — новая версия отвечает параллельно без показа клиентам, сравнение судьёй; канарейка — показ 1–5% трафика с мониторингом guardrail-метрик и автооткатом.

Простыми словами. Новый сотрудник сначала отвечает «в стол», потом берёт 2% звонков.

Когда нужен. После eval gate, до rollout.

Feature flag и реестр версий

Что это. Переключатель поведения без выкладки и реестр согласованных наборов версий (промпт + модель + база + пороги), позволяющие откат за минуту.

Простыми словами. Рубильник, возвращающий вчерашнюю версию целиком.

Когда нужен. Любой релиз агента; мобильный канал особенно.

Контракт качества

Что это. Одностраничная договорённость с заказчиком: сценарии, целевые task success и CSAT, поведение при ошибке, не-цели, как и когда меряем; подписывается до разработки.

Простыми словами. Договор о том, что считаем «работает».

Когда нужен. Старт любого сценария; управление ожиданиями.

OKR ИИ-продукта

Что это. Objective про клиента и бизнес + 3–5 измеримых Key Results с условиями качества и сроком.

Простыми словами. Куда идём и как поймём, что пришли.

Когда нужен. Квартальное и годовое планирование, защита стратегии.

Build / buy / partner

Что это. Решение по каждому слою платформы: строить самим (контроль, дифференциатор), купить (готовые компоненты) или партнёриться (модели, инфраструктура).

Простыми словами. Что печь самим, что купить в магазине, с кем кооперироваться.

Когда нужен. Стратегия платформы, ADR по слоям.

Платформа агентов

Что это. Общие компоненты для всех сценариев: оркестратор, guard, RAG-конвейер, eval-платформа, реестр промптов и моделей, адаптеры инструментов, мониторинг.

Простыми словами. Фундамент, на котором каждый следующий дом дешевле.

Когда нужен. Стратегический тезис; экономика второго и третьего сценария.

Harness

Что это. Всё вокруг модели, что не является моделью: правила, инструменты, контекст-политика, хуки, песочница, субагенты, циклы, наблюдаемость; Agent = Model + Harness.

Простыми словами. Стол, инструменты, памятка и проверяющий вокруг гениального стажёра без памяти.

Когда нужен. При выборе платформы агентов, разговоре о «harness engineering» и оценке dsh.

Cordis

Что это. Плагинный фреймворк под dsh (из экосистемы Koishi): плагины с inject и apply(ctx), сервисы по ключам ctx.*, типизированные события пяти режимов, обратимые эффекты.

Простыми словами. Конструктор, где каждая деталь сама знает, что ей нужно, и сама снимается вместе со всем, что прикрепила.

Когда нужен. При объяснении, почему в dsh «нет привилегированного ядра» и как пишутся плагины.

Seam (capability seam)

Что это. Заменяемая способность dsh: Service Definition (интерфейс на ctx), Service Provider (реализация) и Consumer (обычно инструмент для модели); одна роль — не seam.

Простыми словами. Розетка одного стандарта: прибор любой, лишь бы вилка подходила.

Когда нужен. Когда нужно заменить модель, файловую систему, shell, поиск или песочницу без изменения инструментов.

Профиль и слои патчей dsh

Что это. Профиль — именованная композиция в $DSH_HOME/profiles/<name> (бандлы, плагины, cordis.patch.yml); конфигурация собирается слоями: бандлы → патч профиля → домашний патч → --patch.

Простыми словами. Одежда слоями: базовая, поверх командная, поверх личная, поверх временная.

Когда нужен. При настройке dsh под команду, проверке конфигурации (--dump-config) и переносе политик между средами.

Пресеты dsh

Что это. Наборы инструментов и секций промпта для агента: Standard (полный), PTC (программа против SDK через run_code), Minimal (bash + str_replace_editor), Creator (инспекция runtime и плагины в памяти).

Простыми словами. Комплектации одной машины: базовая, спортивная, голая, сервисная.

Когда нужен. При выборе режима для сценария: поддержка разработки, бенчмарк, автоматизация, разработка плагинов.

PTC (programmatic tool calling)

Что это. Режим dsh (бывший Code mode): модель пишет программу против сгенерированного SDK, инструменты вызываются из кода через run_code в sandboxed Node-рантайме; многошаговая последовательность — за один вызов вместо ~5 раундов.

Простыми словами. Вместо двадцати звонков по одному — один список поручений, который исполняют под присмотром.

Когда нужен. Когда задача требует многих связанных вызовов инструментов и важна латентность и стоимость раундов.

Session log (лог сессии dsh)

Что это. Append-only лог типизированных событий (turn/*, step/*, user|assistant/message, tool/*, approval/*, compaction/*), из которого выводится история модели; основа resume, fork, replay, транскриптов, телеметрии и UI.

Простыми словами. Бортовой самописец: всё, что видел и делал агент, можно переиграть.

Когда нужен. При отладке, eval на реальных прогонах, аудите действий агента и разговоре о контуре данных.

Tools pipeline dsh

Что это. Защищённый конвейер вызова инструмента: tools/pre-execute (allow | deny | cancel | ask) → монотонные guards (только deny) → tools/execute → post-execute (accept | block) → tools/result; аргументы не переписываются.

Простыми словами. Турникеты перед действием: спросить, запретить, выполнить, проверить, записать.

Когда нужен. Когда проектируются банковские политики инструментов: что спрашивать, что запрещать, что проверять в результате.

Approvals dsh

Что это. Одноразовые решения о разрешении действия через waterfall approval/request: исходы allowed-once (единственное разрешение), rejected, cancelled, unavailable; политики ask (по умолчанию) и never (CI); события approval/asked и approval/decided только в лог.

Простыми словами. Охранник, который разрешает один проход и только тот, о котором спросили.

Когда нужен. При настройке интерактивного режима, headless/CI и автоматизаций.

Permission presets dsh

Что это. Пресеты прав workspace-write и danger-full-access, связывающие режим песочницы (SandboxMode) и политику approvals; переключение пишет одно событие permission/preset, достигающее обоих параметров.

Простыми словами. Один переключатель, который задаёт и замок на дверях, и правило «спрашивать разрешения».

Когда нужен. При задании политики по умолчанию для профиля и при объяснении ИБ, что именно ограничено.

Песочница dsh (sandbox)

Что это. Ограничение файловых эффектов подпроцессов через ctx.sandbox.confine(argv, policy): режимы read-only / workspace-write / danger-full-access; backend bwrap или Landlock (Linux), Seatbelt (macOS), ACL restricted-token (Windows, partial); enforcement full | partial; сеть и процессы не ограничиваются.

Простыми словами. Замок на шкафах с файлами; на окна и телефон он не распространяется.

Когда нужен. При оценке ИБ, выборе ОС для раннеров и проектировании периметра.

Компакция контекста

Что это. Сжатие истории при давлении (pressure на agent/pre-step) или переполнении: сначала pruning больших выводов (head/middle/tail), затем summary через ctx.llm.stream(), записанный как user/message с surfaceOp: replace; пары tool-call/result сохраняются; события compaction/start|summary|end.

Простыми словами. Переписать длинный протокол в краткое резюме, не разрывая вопрос и ответ.

Когда нужен. При длинных сессиях, расчёте стоимости (summary — дополнительный запрос) и отладке «агент забыл».

Skills dsh

Что это. Инструкции по требованию: каталог <name>/SKILL.md или <name>.md (kebab-case) из корней по рангу (.dsh/skills 100 → .agents/skills 200 → custom 300 → user 400/500 → bundled 600); список описаний инъецируется как <available_skills>, тело загружается инструментом skill({ name }).

Простыми словами. Справочник на полке: в оглавлении одна строка, страницу открывают при необходимости.

Когда нужен. При прогрессивном раскрытии контекста: правила домена, процедуры релиза, шаблоны документов.

Workflow dsh

Что это. Модельный скрипт оркестрации (dsh-workflow-ptc в PTC-процессе под файловой политикой сессии), запускающий субагентов через agent(), parallel(), pipeline(); результат completed | cancelled | error; dispose() обязателен; события workflow/*.

Простыми словами. Прораб пишет наряд бригадам: кто параллельно, кто следом; результат — когда все отчитались.

Когда нужен. Для многоагентных задач: параллельный анализ модулей, конвейер «план → реализация → ревью».

Субагенты dsh

Что это. Делегирование через ctx.subagents: локальные провайдеры spawn (независимый agentPreset) и fork (наследует композицию родителя), внешние Codex / Claude Code / ACP / dsh-sdk (один прогон, без follow-up); send_message между соседями, interrupt, maxDepth, результат с stopReason.

Простыми словами. Поручить часть работы коллеге со своим столом и получить отчёт.

Когда нужен. Для «контекстных брандмауэров», разделения ролей и использования чужих агентов как исполнителей.

Трасса (trajectory)

Что это. Представление прогона агента по шагам в Web UI dsh: ответы модели, вызовы инструментов и вложенные активности, время, токены; статистика сессии — turns, steps, model time, tool time, TTFT, decoding time; строится из лога сессии.

Простыми словами. Запись полёта с отметками времени и затраченного топлива на каждом манёвре.

Когда нужен. При отладке «почему агент сделал это», оценке стоимости и латентности и разборе инцидентов.
